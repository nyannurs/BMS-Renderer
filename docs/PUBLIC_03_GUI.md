# GUI Reference (`bms_renderer_qt.py`)

The PySide6 frontend: the main window, dialogs, custom widgets, background workers, and the entry point.

## Startup
`main()` enables multiprocessing support, sets the **Fusion style once** (theming depends on this), installs the application stylesheet (button padding, muted-label colour, and a styled tooltip), and shows the main window. The logo and app icon are embedded as base64. The player and Discord modules are imported defensively, so the app runs if either is unavailable.

On shutdown, a handler closes the window (which performs the real cleanup), terminates any lingering worker processes, and then exits the process immediately. This is wired to the window-close path and to interrupt signals (so Ctrl+C in a terminal quits cleanly), and it avoids a Linux hang where the interpreter would otherwise wait on worker-pool helper threads at exit.

## Custom widgets
- `CollapsibleAlbumView` — the sectioned, collapsible album grid used in several tabs.
- `MarqueeLabel` — the now-playing title; it inherits the palette text colour (so it reads correctly in both light and dark themes). It is clickable: clicking it loads the playing song into the right info panel, the same as selecting it in a list. It only presents as interactive when a song is playing — a pointing-hand cursor, a tooltip, and a blue-bold hover state appear only then; with nothing playing it is inert.
- `WaveformBar` — a click-to-seek waveform under the transport. It can be swapped for a moodbar (a colour-per-moment spectral bar) via the `song_visualizer` config key; both scrub identically.
- `VolumeTriangle` — a triangular volume control; the mouse wheel adjusts volume over it.
- `EQVisualizer` — a foobar2000-style spectrum analyser in the top bar, centred in the window. It runs its own 60 fps timer, takes an FFT of the audio at the current playback position, and maps the result to log-spaced frequency bands. Three details matter and were each arrived at the hard way: it reads at the **audible** position (`position_seconds()`, which subtracts output latency) rather than the raw feeder cursor, or it visibly reacts *before* you hear the sound; it takes the **maximum** bin per band rather than the mean, since averaging flattens the dynamics into a lifeless mid-range; and it applies Web-Audio-style time smoothing to the magnitudes, because raw per-frame FFT output is inherently jittery — removing all smoothing makes it *choppier*, not snappier. Bars rise instantly and fall under frame-rate-independent gravity, so on pause they glide to the floor instead of vanishing. When nothing is playing it stops repainting entirely (a 60 fps idle repaint measurably competes with the render workers) and hides its grid lines.
- `_CodecPerfGraphic` — a three-bar codec guide (Quality / Efficiency / Speed), where a longer bar is always better; the middle bar is size *efficiency*, so a long bar means smaller files.

## Background workers
All are `QThread` subclasses that run at low priority and emit signals back to the GUI:
- `ScanWorker` — runs the library scan. It can be asked to stop, so closing the window during a long initial scan no longer leaves the thread running as the application tears down around it; a partial scan keeps what it parsed and deliberately skips the removal of charts it never got to.
- `RenderWorker` — offline audio render; builds job tuples and runs them in a process pool; resolves cover art per item.
- `BGAWorker` — offline BGA render. It sorts queued charts into three job types: image-sequence BGAs (encoded frame by frame), video BGAs (muxed, optionally as a lossless copy), and — when enabled — charts with **no** BGA, which are rendered as plain audio files so one batch covers the whole queue instead of silently dropping them. It reports a corrected total once sorting is done, and logs each chart's warnings. A failed item logs the actual ffmpeg error rather than a bare "failed".

Output files (audio and BGA) are named from the song's title, with characters illegal in filenames replaced and a trailing chart extension stripped — so an untitled chart, whose title falls back to its filename, produces `song.mkv` rather than `song.bms.mkv` (which Windows would display as `song.bms` with extensions hidden).

**Names are also made unique within each render batch.** The difficulties of one BMS song almost always share a `#TITLE`, so naming by title alone meant two queued charts resolved to the same output path (and the same temporary file) — one render silently overwrote the other while both reported success. A title that is unique in the batch is left untouched, so ordinary filenames are unchanged; where two charts collide, each gets its own chart filename appended (`Black Lotus [7another].flac`), which is unique within a song folder and identifies which chart it is. A numeric suffix covers the remaining case of the same title *and* the same chart filename in two different folders. Both the audio and BGA renderers use this, and any new render path should too.
- `PlayWorker` — renders one chart to a buffer for in-app playback.
- `ThumbWorker` — loads grid thumbnails.
- A BGA-detection worker — runs `detect_bga` off the GUI thread for the right-panel indicator.
- A table-fetch worker — runs `fetch_table` off-thread.

`_apply_process_priority` sets the render process priority (Windows `SetPriorityClass` / POSIX `nice`); High and Above-Normal may require elevation on Windows.

The offline render workers create their process pool with the **spawn** start method. On Linux the default fork method duplicates the application's Qt/X11 state into each worker, which causes segfaults when the pool or the app tears down; spawn uses fresh interpreters and avoids this. Aborting a render terminates the worker processes rather than waiting for in-flight jobs to finish.

## Dialogs
- **BGA export** (opened by "Render All BGA in Queue" and "Render All BGA in Playlist") — video and audio codec dropdowns, bitrate sliders mirrored to manual spin boxes, the codec guide graphic, and a process-priority dropdown. Selecting FLAC switches the audio control to a compression-level slider (0–8, default 8); WAV disables it. OGG gets a wider bitrate range (about 45–500 kbps) than the MP3/AAC range (64–320), reflecting what Vorbis can actually encode. "Default" shows the baseline value but locks it as an indicator. Returns the encode options and priority.

  It also shows what is actually in the batch ("9 queued — 2 video BGA, 3 image-sequence BGA, 4 without a BGA"), so a user isn't left configuring codecs for a queue with nothing renderable in it. Working that out means inspecting every queued chart, so the result is handed to the render worker rather than recomputed there — the batch used to be classified twice, once to build the dialog and again to start the render. and a live **Output:** indicator showing whether the current settings will produce `.mp4` or `.mkv` — the container switch is otherwise silent and can waste an entire batch.

  **NVENC entries are disabled when the hardware probe fails**, with ffmpeg's own reason in the tooltip. **Lossless remux** greys out the entire Video group *only when the batch is purely video BGAs*; if any image-sequence BGA is present those settings still apply to it, and an in-place note explains which charts each control affects. Audio codecs are **not** restricted in remux mode — any non-default audio already forces the mkv container, so lossless video does not require lossless audio.
- **Audio export** (opened by "Render All in Queue" and "Render Playlist") — format, thread count, a format-specific quality control, and process priority. FLAC uses compression 0–8 (default 8); OGG uses VBR quality 0–10 (default 6); MP3 runs left = smallest file to right = best (320 kbps CBR, the default at the far right); WAV has no quality control. The quality value label has a fixed width so the slider doesn't resize as the label text changes. It returns quality only when the settings differ from the defaults, so unchanged settings produce identical output.
- **Render progress** — a modal dialog with a green progress bar, used by the audio, playlist, and BGA renders. The bar shows **real sub-item progress**, not just completed items: each worker process reports its own 0–1 fraction to a file and the dialog polls them, so a single long encode advances continuously instead of sitting at 0% until it finishes. It never runs backwards — whichever is further along, the reported fraction or the completed-item count, wins. It includes an **Abort** button that stops the render: it cancels queued work and terminates the worker processes already running (an aborted render may leave a partial output file, since it is stopped mid-write).
- **Art viewer** — a resizable window opened by clicking the right-panel art preview. A scaling dropdown in the top-left offers smooth, Lanczos, bicubic, nearest-neighbour, and 1:1 actual-size modes; the choice auto-saves. Right-clicking offers "Copy image to clipboard" (the full-resolution original). When the song folder holds several images, a prev/slider/next bar pages through them. The image scales to the window (1:1 shows true pixels in a scrollable view), and the window remembers its size and position between sessions. It is modeless, so playback continues while it is open.

## Main window
A five-tab layout — Library, Discovery, Tables, Custom Playlists, Queue — with the dark-mode toggle in the top-right corner of the tab bar.

The Library tree has a **Charts** column that is hidden unless "Songs only" is on. In that mode a top-level row is a *song* and its children are that song's charts, so "Notes" always means notes and "Charts" always means how many charts the song has — previously one column carried both meanings depending on row depth, which made it unreadable and its sorting meaningless. Saved column widths are validated against the current column count, so a config written by an older version can't apply widths to the wrong columns. The right panel holds the tag editor, the BMS-information panel, the per-song art picker with a BGA indicator, and the whole-queue cover controls. The transport bar holds the playback controls, audio-device button, waveform, volume control, and shuffle/loop toggles, with a log pane below.

### Theming
The app uses the Fusion style application-wide, set once at startup; **the style is never switched at runtime** — light and dark are a palette swap only. Applying a theme swaps the application palette and then re-polishes every widget (`unpolish`/`polish`); it does **not** assign palettes to individual widgets, because doing so permanently detaches a widget from the application palette. Muted/grey labels are styled through the application stylesheet so they remain readable in both themes. The transport's media icons (previous, play/pause, stop, next) and the logo are inverted to white on dark themes so they stay visible. The logo at the top-right opens the project's GitHub page when clicked; on startup the app quietly checks GitHub for a newer release, and if one exists the logo gently pulses blue (in both light and dark themes) and its tooltip shows the available version — clicking still opens the GitHub page to download it. The check is fail-safe: offline or rate-limited, the app behaves exactly as normal. Buttons share a common padding, minimum height, and icon size so text-only and icon buttons match; the compact transport/art icon buttons opt out via an object name.

### Playback and media keys
The transport methods start, stop, advance, and seek playback, honour shuffle/loop, and poll for auto-advance. **The playing song and the selected song are tracked by path, not by row index.** The queue is mutated while the user browses — rows are removed automatically as charts finish rendering — and a stored row number silently starts pointing at a different song once anything shifts above it. That caused the wrong track to play next, the info panel to show the wrong song, *and* tag edits to be written to the wrong queue entry. Both are now re-derived from the song's path at the moment they are needed. If the playing song is itself removed mid-playback, playback resumes from where it was.

"Previous" restarts the current song when more than three seconds in, and only skips to the previous track near the start — standard music-player behaviour. Shuffle and loop states persist across restarts. Media keys are bound through application-scoped shortcuts (they fire when the app has focus, not system-wide): play/pause, stop, next/previous, volume up/down, and mute, with Ctrl-based fallbacks including Ctrl+Space for play/pause. The now-playing marker tracks only the marked rows rather than scanning the whole list, which matters at large library sizes.

Next to the now-playing title, a small "Playing from:" line shows where the current song was started (Library, Discovery, Tables, Custom Playlist, or Queue).

The song-scrubbing visualizer under the transport can be either a waveform (default) or a moodbar, selected with the `song_visualizer` config key (`"waveform"`, `"moodbar"`, or `"spectrogram"`). The moodbar colours each moment of the track by its frequency content — bass toward red, mids toward green, treble toward blue — giving the whole song a colour signature. The spectrogram instead shows a frequency heat-map over time (low frequencies at the bottom, high at the top, brightness = energy) so you can see the song's layers — kick, hats, melody — as separate bands. Both support click-and-drag seeking identically, and both blank out the moment you pick a new song so the previous track's bar doesn't linger while the new one renders. The time readout beside the transport is hidden when nothing is playing. You can start a song by selecting it in any tab (Library, Discovery, Tables, Custom Playlists, or Queue) and pressing the play button, in addition to double-clicking or right-click → Play. While a song plays, the app quietly pre-renders the next track in the background so hitting next (or auto-advance) starts instantly instead of pausing to render; this is skipped when shuffle is on (no predictable "next"). During the initial library scan and cache load at startup, the visualizer area shows a progress bar with a "Loading library…" label instead of an empty waveform; it starts as an indeterminate animation while the scanner counts the library, then shows real scan progress as a percentage, and disappears once the library is ready.

The app can write the currently-playing song to a file in the program directory for use as an OBS source, controlled by two config keys that appear automatically (off by default): `nowplaying_output` enables it, and `nowplaying_format` selects the layout. In `txt` mode it writes `nowplaying.txt` with the title and artist on separate lines — point an OBS Text source at it. In `html` mode it writes a styled card (`nowplaying.html` plus a companion `nowplaying.json` data file): a square album-art image (resolved the same way as the library grid, letterboxed to fit with black bars, or a black "(no images)" square when the song has no art) next to the title in a large font and the artist smaller. The HTML card polls its data file and updates itself on each song change without a manual refresh; point an OBS Browser source at `nowplaying.html` and size it 960×480. Both modes update on song change and clear when playback stops.

### Tabs
The Library tab is a flat sortable table; the numeric columns (BPM, Notes) sort by value rather than as text. Discovery is an art grid. Tables shows difficulty tables as a level/song tree; the level rows sort by difficulty (so ★2 precedes ★10, and a non-numeric level like "???" sorts last) and the view defaults to difficulty order. In album view each level is a separate grid, and both the "Add selected" button and the right-click menu gather the selection across **all** level grids so multi-selection spans levels. Custom Playlists has a "Date added" column (sorted chronologically) and both a "Render Playlist" and a "Render All BGA in Playlist" button; Queue manages the render queue. Render buttons open the appropriate export dialog and show the progress dialog. As each queued chart finishes rendering (audio or BGA), it is removed from the queue — matched by its file path, not by its row number. Renders run in parallel and finish out of order, so a positional scheme removed the wrong rows and left successfully-rendered charts behind. Charts skipped during a BGA render (those with a video BGA or none) remain. Thread-count and format selection live in the export dialogs.

The Custom Playlists "Date added" column is playlist-specific: songs are stamped with the time they were added, and the column shows a date but sorts by the underlying timestamp. Entries added before this column existed fall back to their saved insertion order.

Because the Custom Playlists table is sortable, each row remembers which playlist entry it represents rather than relying on its visual position — after a sort, row order no longer matches the saved playlist order, so selection, render, and remove all look the entry up by that stored identity. Auto-advance instead follows the **visual** row order, so the song shown directly below the current one plays next; it re-locates the playing row by path, so re-sorting mid-playback stays correct. This keeps the info panel showing the selected song and ensures remove deletes the right entry. The "?" context-help button is disabled application-wide, so it no longer appears in dialog title bars on Windows.

### Tags and art
Tag fields auto-save edits. Hovering any right-panel field (the BMS-information labels and the tag inputs) shows its full value as a tooltip positioned to the right of the field, so truncated values stay readable. The per-song art picker cycles through a folder's images, supports assigning a plain black square as a cover, and (when clicked) opens the art viewer. The BGA indicator shows whether the selected chart has a renderable sequence BGA. Cover art can be set per song or for the whole queue.
